# 启动后等待主窗口就绪

## 用户诉求

修复应用进程已启动、主窗口稍后才出现导致 getApp 提前返回 cgWindowNotFound 的问题。启动后的窗口等待上限采用 3 秒；完成验证后发布依赖，交给用户编译实测。

## 实现与边界

- 仅 initializeAppSnapshot 实际 launch/reopen 成功后进入 ApplicationWindowWait；普通读取、已有窗口绑定和输入动作不增加等待。
- 单调时钟设置 3 秒截止时间，每次未就绪最多等待 100ms；准备完成即结束。轻量探测窗口 AX/CG 元数据，单次 AX 消息上限 50ms，并收敛到剩余预算。不循环生成截图或完整 AX 树。
- 复用原窗口元数据匹配规则，默认截图路径不变，跨 Space 查询保留。
- 绑定系统打开回调返回的 PID/启动时间，探测前后与快照发布前检查身份。协作取消、权限错误和进程消失不重试。
- 超时后保留 pending initialization，不重放 launch/reopen；继续支持既有只读恢复及别名保护。
- 3 秒是窗口就绪等待预算，不包含启动回调耗时和完整快照。AX/CG 同步系统调用无法保证硬实时中断；宿主终止 Helper 的停止机制保持不变。

## 验证

- 新增确定性时钟测试覆盖立即/延迟就绪、超时、慢探测、权限错误、取消、进程身份变化、一次启动和无窗口只读恢复。
- 完整 Swift 测试通过：538 项 XCTest（8 项跳过），65 项 Swift Testing；新增 11 项启动等待测试全部通过。
- 既有预览 80ms 实时时序测试初跑出现波动，独立复跑及最终完整回归通过；本轮未修改预览代码。
- 新增 Swift 文件及窗口探测新增代码的 SwiftFormat、SwiftLint 检查通过；原有大文件的存量 lint 问题未扩展修改。文档检查与 git diff --check 通过。
- 不启动或替换用户运行 App；真实冷启动由用户重新编译后验收。
