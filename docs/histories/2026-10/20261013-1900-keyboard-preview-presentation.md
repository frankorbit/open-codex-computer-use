## 2026-10-13 | Task: 键盘输入时稳定本地预览并显示输入提示

### Execution Context
- Agent: Codex
- Runtime: 本地 macOS 工作区

### 用户诉求
上一轮边缘光标修复提交并推送；排查计算器输入时光标停在旧位置、预览闪烁；键盘输入时隐藏旧光标并提供状态提示。

### 原因与边界
- 实际 helper 日志确认后半段是连续 `type_text`、`sky_key` 输入，光标停在旧点击位置不代表输入卡死。
- 后台键盘合成焦点会经历获取/释放，目标可能改变焦点外观；原预览又把所有非完整、非 idle 帧立即清空。缺少该次逐帧状态，不能断言此次闪烁只由其中一项引起。
- 本轮只改展示。真实键盘事件、接收窗口校验、焦点清理、菜单 lease、权限和模型截图不改变，不自动重放输入。

### 实现
- Dispatcher 在现有输入作用域区分键盘工具，清除旧虚拟光标并显示顶部静态键盘图标和“键盘输入中”。连续输入合并提示，结束后 650ms 收起，鼠标输入立即收起；加入 AX 状态，窄预览避开收起按钮。
- 后台 focus begin/end 只通知预览，暂缓合成并保留最新帧；每轮首次暂停建立不可续期的 300ms 绝对截止，结束后的 150ms 稳定等待取两者较早时间；到期显示最新帧，再允许后续事件开启新一轮。长文本和连续短按键均不能无限冻结。重置取消延迟回调并清除截止时间。
- 区分临时 started/解码缺帧和真正不可用状态，缺帧最多保留旧画面 250ms；恢复新帧或切换窗口时取消旧等待。blank/suspended/stopped/未知状态立即清空。添加不含屏幕正文的状态诊断日志。
- 提取 SCK 流构造与帧事件处理，保留原来单窗口过滤、缓冲深度和采样队列。

### 连续输入复审补修
- 复审发现此前相对计时器会被每次 focus begin/end 续期，连续短按键可能无限延迟画面刷新。
- 改为 `ContinuousClock` 绝对截止；主线程尚未处理到期任务而新事件先到时，先放行旧帧。已取消的旧回调不能结束新一轮保持。
- 新增四项回归：连续短按键不能续期、focus release 不能延长硬截止、稳定后可以提前恢复、尚未调度的到期任务不能被新事件掩盖。前两项在旧实现出现三个断言失败，修复后全部通过。
- 相同 20 次短按键隔离实验：旧实现约 1.71 秒内零次放行；修复后约 1.76 秒内五次放行，静默后完成最后一轮恢复。该实验调用生产展示状态类，不操作真实 App。
