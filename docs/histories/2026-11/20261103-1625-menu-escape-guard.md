# 菜单 Escape 歧义保护与稀疏表格观察

## 请求与根因

继续修复 Numbers 真机验收：不能为了关闭菜单而取消旧草稿，也不能因 AX 未暴露 A1 就猜索引或重放输入。菜单栏的选中标记与弹层存在只证明观察状态，不证明 PID 键盘事件由菜单接收。此前 Escape 后旧单元格退出编辑、未提交值消失；新表格 AX 则仅返回行列，不暴露 cell。

## 实现

- `KeyboardEscapeGuard.swift`：只有普通 Escape 且当前快照存在菜单证据时检查实时焦点 PID 和菜单角色；复用有界 AX reader，失败不吞掉。
- `ComputerUseService.pressKey`：在合成焦点准备前及提交前调用保护，auto/sky_key 都执行；无菜单的 Escape、其他按键、fixture、鼠标/粘贴/写值路线不变。
- `AccessibilitySnapshot.swift`：稀疏表格仅增加有界观察提示，不创建目标、不补 AX 查询、不自动点击。
- Web Runtime 指引强调保留旧编辑、先截图核对行列、不能吞掉等待超时再继续输入；同步源清单哈希，不改变 native pin。
- 新增完整 MCP 入口及真实 Runtime 会话回归，覆盖准备前拒绝、焦点变化、权限/取消/超时、未知结果只发送一次、普通按键兼容与无 AX 观察。

## Review 与限制

- 没有修改点击机制、权限分类、超时值、云端轮数、重试或停止规则。没有向真实应用发送新的编辑、Return、保存或关闭操作。
- 新增 AX 查询只影响观察到菜单的普通 Escape；两阶段各自受既有 2 秒校验预算约束，因此此分支可能增加耗时。同步 AX 查询仍在返回后检查取消。
- 某些可见原生菜单不暴露菜单焦点，此时会保守拒绝 Escape。菜单未被快照观察到时，本保护不提供额外保证；菜单成功接收仍须观察效果，不能把发出视为成功。
- 单元格观察提示属于初次目标发现指引，不保证模型完成视觉定位；完整真机任务仍需新签名构建验收。
- 默认 SDK 27.2 的 Date.>= 崩溃在未修改 HEAD 和独立 Foundation 最小程序上复现；最小程序明确报告缺失系统 Foundation 符号。默认并发预览测试 3 用例 / 5 断言也在 HEAD 复现。SDK 26.5 串行通过不等于默认构建/并发配置通过；本次未修改这两类独立问题。
