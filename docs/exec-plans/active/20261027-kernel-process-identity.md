# 使用内核启动时间验证窗口观察身份

## 目标与范围

修复 Finder 正常存活、AppKit `launchDate` 缺失时被误判为进程变化。仅修改 macOS 快照恢复和初始化的进程身份依据，不修改点击机制、停止规则、打开次数或等待预算。

## 证据与方案

- 实机 Finder 打开默认窗口成功，但随后身份检查失败；只读进程元数据确认 `launchDate=nil`。
- `RunningAppDescriptor` 创建时捕获 PID 与 `PROC_PIDTBSDINFO` 的启动秒/微秒，使用整数比较。
- 原 AppKit 对象在内核读取前后必须存活且 PID 一致。读取失败或不完整时保留空身份，后续拒绝，不能补绑到复用的 PID。
- `bound` 仅取冻结身份，`current` 读取当前内核身份；身份缺失或改变仍停止，不重发 launch/reopen。
- 打开后的错误不能宣称整个操作没有副作用；明确不发送后续输入、不重放上一步。

## 风险与边界

- 内核读取增加系统 API 依赖，权限或未知失败保守拒绝，不降级为只比 PID。
- AppKit 对象与内核读取不是原子事务；保留双侧存活校验，不宣称消除所有构造瞬间竞态。
- TargetedQuery 与 SkyClickMenuFocus 的身份策略不在本次范围。
