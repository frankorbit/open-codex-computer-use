# Finder 文本粘贴接收者

## 目标与证据

第6题新建文件夹后观察到选中文字，随后 paste_text 生成 Text Clipping。原始 trace 确认中间没有第五次输入；paste 后焦点为 ListView。源码 paste_text 只校验窗口，且经菜单键等价项分派，不能保证文本编辑接收者。现有证据不能确定焦点在哪一刻丢失，也不能将其归因到 selection 观察修复。

## 范围

- Finder 的 paste_text 要求实时可编辑接收者，在准备前与提交前复验同一 AX 身份、窗口和 PID。
- Finder 文本粘贴不调用文件管理菜单 Paste，直接对经过验证的编辑接收者发送一次 PID Cmd+V；失败不回退、不重放。
- 其他应用维持现有无 AX 文本焦点兼容路径；press_key 的文件复制/移动语义不变。
- 增加脱敏的 paste 输入诊断；不记录文本、文件名、剪贴板内容。
- 回归覆盖准备前拒绝、准备后失焦、剪贴板阶段失焦、取消、未知结果及非 Finder 兼容。

## 验证边界

下载目录的既有失败产物保留，不重新发送新建/粘贴/移动。Codex 独立目录导航未完成，不能算对照通过。自动测试只证明路由与停止语义，Finder 实机命名成功仍需新签名包的独立测试。
