# 菜单 Escape 接收者与稀疏表格观察

## 目标与证据

真机验收中，菜单仍标为选中时发送 Escape，PID 键盘事件落入 Numbers 的文稿编辑者，未提交内容被取消。随后新表格只暴露行列、未暴露 AXCell，模型按文本索引查找 A1 失败。不能把菜单选中视为键盘接收证明，也不能把未暴露单元格视为仍在加载。

## 范围与约束

- 对观察到菜单的普通 Escape，合成焦点准备前和提交前检查实时焦点的 PID 与菜单角色；无法证明则发送前停止。
- 不新增自动取消、焦点切换、重试或输入路径回退。没有菜单证据的普通 Escape 及其他按键保持原路径。
- 稀疏表格仅补充观察提示：初次选择目标前看新截图、确认行列，不猜索引，不把首个数据单元格当作 A1。
- 保留权限、取消、超时、未知结果及禁止重放规则；不改轮数和超时配置。
- 现存草稿不修改，不通过重放业务操作验证修复。签名 App 仍指向已提交旧版本，本次未提交代码不能视为已实机验收。

## 验证计划

- 原生完整 MCP press_key 入口覆盖 auto/sky_key、准备前拒绝、准备后焦点变化、真实权限错误、取消、超时和发送后未知结果。
- 验证无菜单的 Escape 与非 Escape 按键不增加菜单 AX 查询；菜单状态的缺失不伪造肯定证据。
- 稀疏表格提示覆盖正常单元格、非表格及 include_ax=false。
- Web Runtime 真实会话入口覆盖文档注入和失败不自动重试；源文件清单哈希一致。
- 运行定向与完整回归，review 变更，不修改既有并发预览计时规则。

## 风险边界

一些真实原生菜单不暴露 AX 键盘焦点；这种歧义状态会拒绝 Escape，不能声称能通用关闭菜单。快照未观测到菜单时本保护不提供额外保证；这不是全局键盘接收证明。截图提示是模型指引，不是自动坐标选择。
